# [RFC] Add f8E5M3FNU type

Status: Draft<br />
Initial version: 10/09/2026<br />
Last updated: 10/09/2026<br />
Discussion thread: [PR#3037](https://github.com/openxla/stablehlo/pull/3037)

## Overview

NVIDIA hardware supports `f8E5M3FNU` as a block-scaling format, which we would
like to make available in XLA and JAX. This type is described as `ue5m3` in PTX
ISA documentation[^1], and is available as of PTX ISA 9.4 and `sm_107f`.

The type is already available in LLVM APFloat as `Float8E5M3FNU`[^2], in
MLIR[^3], and is being added to `ml_dtypes` as `float8_e5m3fnu`[^4].

This RFC is similar to other recent proposals adding FP8 types, e.g.

- [20240808-f8E4M3_f8E3M4.md](20240808-f8E4M3_f8E3M4.md) ([PR#2486](https://github.com/openxla/stablehlo/pull/2486))
- [20241001-microscaling-formats.md](20241001-microscaling-formats.md) ([PR#2581](https://github.com/openxla/stablehlo/pull/2581))


## Details

`f8E5M3FNU` is similar to `f8E5M2`, except that the sign bit is removed in favor
of an additional mantissa bit for increased precision.

`f8E5M3FNU` will be added to StableHLO as a new type.

`f8E5M3FNU` is an 8-bit floating point type with no sign bit, 5 bits exponent
and 3 bits mantissa (`0bEEEEE'MMM`). The `FNU` suffix indicates that the type

- has no representation of infinity (`F`)
- has non-IEEE NaN encoding (`N`, NaN represented by `0b11111'111`)
- is unsigned (`U`).

|                     | f8E5M3FNU                                           |
|---------------------|-----------------------------------------------------|
| Exponent bias       | 15                                                  |
| Exponent range      | -14 to +16                                          |
| Min normal value    | `0b00001'000` = 2<sup>-14</sup>                     |
| Max normal value    | `0b11111'110` = 2<sup>17</sup> - 2<sup>14</sup>     |
| Min subnormal value | `0b00000'001` = 2<sup>-17</sup>                     |
| Max subnormal value | `0b00000'111` = 2<sup>-14</sup> - 2<sup>-17</sup>   |
| NaN                 | `0b11111'111`                                       |
| Infinity            | N/A                                                 |
| Zero                | `0b00000'000`                                       |

## Arithmetic semantics

Conversion of negative values to `f8E5M3FNU` is left as implementation-defined.
NVIDIA hardware converts negative values by converting the absolute value.

Conversion of too-large values results in `NAN` (no saturation).

As a scaling type, there is no hardware support for arithmetic operations on
`f8E5M3FNU` beyond conversion today. Therefore further arithmetic operations are
left unspecified, in particular those which may yield negative results.
